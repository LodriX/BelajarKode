# Agent notes

## Shape of the app

- React 19 + Vite 8 source in `src/`; `npm run build` emits **one self-contained `BelajarKode.html`** (JS, CSS, fonts, and curriculum inlined) plus `buku-belajarkode.html`. Both are copied to the repo root by `scripts/release.mjs`.
- The shipped app must keep working from `file://`: no backend, cookies, service worker, PWA, runtime `fetch` of curriculum, or Web History routing. Use hash routes.
- `index.html` is only the Vite entry. Never tell users to open it; they open `BelajarKode.html`.
- `content/` is the content source: `content/index.json` holds metadata/roadmap/tools. Rewritten modules use `content/mXX/module.json` + `lesson-*.json`; legacy modules still use `content/mXX.json`. `data/curriculum.json` is generated by `scripts/build-content.mjs` and imported at build time. Never edit the generated file by hand.
- Start page lives at `#/mulai`; setup checklist state is stored per profile in `state.setup`. It is not a lesson module.

## Commands

- `npm run dev` regenerates content + book, then serves Vite on 5173.
- `npm run content:build` composes `content/` into `data/curriculum.json`.
- `npm run content:check` builds and validates schema, IDs, quiz answers, strict word counts, and source policy.
- `npm run sources:check` checks the source registry URLs over the network; it is deliberately separate from `npm run build` so builds stay offline.
- `npm run book` rebuilds content + `buku-belajarkode.html`.
- `npm run build` = content check → book → single-file build → copy artifacts to root.
- `npm run test` (Vitest), `npm run lint` (ESLint), `npm run smoke` (file:// E2E), `npm run a11y` (axe).
- Smoke/a11y scripts need a local Chrome; override with `CHROME_PATH`.

## Content and book

- `book/deep-dive/01..05.html` contains ~65 KB of prose that exists nowhere in `content/`. Do not delete or regenerate it; `scripts/build-book.mjs` injects it verbatim.
- The book generator requires exactly 5 deep-dive files and a non-empty curriculum; do not reintroduce hardcoded lesson/module counts.
- Lesson schema v2: `objectives`, `prerequisites`, `terms`, `sections` (body/code/callouts/checkpoint), `practice[]`, `troubleshooting[]`, `quiz.questions[]`, `resources`, `summary`. Legacy lessons are normalized by the build script.
- Lesson schema v3.1 adds `syntax[].readAs`, `sections[].code.annotations[]` (`line`, `code`, `note`), `conventions[]`, and `next`. For v3.1, the validator requires a `cara-membaca` section, at least three conventions, a non-empty `next`, a `readAs` on every syntax card, and annotations whose `code` matches the referenced code line.
- Lesson schema v3 adds `outcome`, `depth` (`fondasi`/`integrasi`/`capstone`), `syntax[]` (`token`, `meaning`, `example`, `output`, `pitfall`), progressive `practice[].hints[]`, and `verification`. Register pilot lessons in `contentPolicy.requireV3`; their word count must fit `contentPolicy.depthWordBands`.
- `content/index.json` has `contentPolicy.requireV2`; add module IDs there as they are rewritten to enforce 3 quizzes, 3 practice items, 3 troubleshooting entries, and formal “Anda”. Prefer schema v3 for new rewrites.
- Trusted sources live in `content/index.json` → `sources` with `id`, `title`, `publisher`, `url`, `tier`, `version`, `accessedAt`, and optional `license`. Rewritten lessons reference them with `resources: [{ sourceId, note }]`; do not paste untracked URLs into a lesson.
- `sourcePolicy` applies to `requireV2` modules and `requireV3` lessons: at least two registry sources, one `standard`/`official`, HTTPS URLs, valid access dates, unique IDs/URLs. Add sources only from standards bodies, official vendor docs, government sites, or reputable university/education sources.
- Code examples that need browser APIs such as `localStorage` or real DOM must set `section.code.lab: false`; the Lab runs JavaScript in a worker and cannot execute those APIs.
- Sources are links, not bundled text. Paraphrase in Indonesian and verify version-sensitive claims against the pinned documentation.
- Generated artifacts (`BelajarKode.html`, `buku-belajarkode.html`, `public/`, `dist/`) are build output; edit `src/`, `content/`, or `scripts/`, not the artifacts.

## Auth and storage

- Local profiles only. PIN 6 digits hashed with `@noble/hashes` PBKDF2-SHA256 (150k iterations, random salt); do not switch to WebCrypto without testing `file://`.
- PIN locks a profile, it does **not** encrypt `localStorage`. Keep the UI copy honest.
- Keys: `bk.v2.profiles`, `bk.v2.state.<id>`, `bk.v2.session`, `bk.v2.remember`. Legacy key `belajarkode-user-v1` must remain importable.
- Profile state is normalized and XP/badges are recomputed by `reconcile()`; keep mutations idempotent and going through `AppStore.update()`.
- `state.quizzes[lessonId]` stores `{ answers: { questionId: { choice, correct, attempts } }, correct, attempts }`; `attempts` is the max across questions so a first-try multi-question quiz still earns first-try XP.
- `state.reading[lessonId]` stores section IDs read; `state.setup` stores the Start checklist.
- `state.settings` stores `appearance`, `contrast`, and `motion`; normalize unknown appearance values back to `nyaman`.

## UI constraints

- Warm mint dashboard: Plus Jakarta Sans for UI, IBM Plex Mono for code, warm charcoal shell, soft parchment reading surfaces, sage-mint accent. Cards are allowed but should form 2?3 intentional surfaces, not a mosaic. No gradients/glassmorphism/emoji icons.
- Appearance modes live in `state.settings.appearance`: `nyaman` (default warm dim), `terang` (warm light), and `malam` (dark reading surfaces). Apply them through `data-appearance` on `document.documentElement`; keep `data-contrast` and `data-motion` independent and apply high contrast last in the cascade.
- Minimum functional text is 12px, UI body 16px, lesson body 18px. New UI must pass `npm run a11y` (currently zero WCAG 2.1/2.2 AA violations) in every appearance mode and keep mobile layouts usable at 390 px. Use deep mint on light paper and light mint on dark surfaces for AA/AAA contrast.
- Respect `prefers-reduced-motion` and the in-app contrast/motion settings.
