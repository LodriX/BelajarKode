PENDALAMAN 1 · 01 pengantar dan roadmap

Buku Belajar Pemrograman dari Nol ke Full-Stack Web dan Mobile

Edisi: Oktober 2026
Bahasa: Indonesia
Jalur utama: fundamental → HTML/CSS/JavaScript → SQL/PostgreSQL → PHP/Laravel → REST API → Dart/Flutter → quality, security, deployment.
Sasaran: pemula mandiri yang ingin mampu merancang, membangun, menguji, dan memelihara aplikasi web dan mobile.

Cara menggunakan buku: Baca secara berurutan, ketik sendiri contoh kode, jalankan, ubah, lakukan latihan tanpa melihat solusi, catat kesalahan, dan simpan hasil dalam Git. Buku ini bisa dibaca offline; untuk memasang SDK, paket, emulator, atau mengakses dokumentasi resmi, tetap diperlukan internet pada saat persiapan.

Pengantar: kemampuan yang akan Anda dapatkan

Setelah menyelesaikan jalur ini, Anda seharusnya dapat: menerjemahkan masalah menjadi algoritma; membaca dan menulis kode dengan struktur jelas; membuat halaman web yang responsif dan aksesibel; merancang database relasional; membangun API dengan autentikasi dan otorisasi; menghubungkan Flutter dengan API; menguji perilaku sistem; menyiapkan deployment, backup, logging, dan prosedur rollback. Kemampuan yang diukur adalah hasil kerja dan penjelasan Anda, bukan jumlah jam menonton tutorial.

Estimasi realistis: 52 minggu × 4-5 jam ≈ 210-260 jam. Modul inti (m00 sampai m12) diperuntukkan 49 minggu; 3 minggu terakhir untuk modul opsional, dan 1 minggu buffer di ekor kurikulum untuk melengkapi gerbang yang belum lulus. Ini adalah target belajar, bukan jaminan penguasaan. Bila Anda baru mulai benar-benar dari nol, tambah waktu sesuai kebutuhan. Bila sudah tahu dasar HTML atau Laravel, tetap ikuti tes keluar setiap fase sebelum melompat.

Mengapa satu jalur teknologi?

Pemula sering terjebak mempelajari React, Angular, Vue, Next.js, Node, PHP, Go, Python, Flutter, Kotlin, sekaligus. Masalahnya bukan kualitas teknologinya, tetapi pergantian konteks yang menghalangi penguasaan konsep. Jalur yang digunakan buku ini sengaja fokus:

  • Bahasa pertama praktik: JavaScript, karena langsung terlihat di browser dan membangun kebiasaan logika serta event-driven programming.
  • Fundamental web: HTML semantik, CSS, JavaScript tanpa framework, lalu TypeScript sebagai pendalaman keamanan tipe.
  • Data: SQL dan PostgreSQL, termasuk relasi, indeks, transaksi, dan pemodelan. MySQL tetap valid bila proyek membutuhkan; SQL fundamentalnya dapat ditransfer.
  • Backend utama: PHP modern dan Laravel (version 13 sebagai rujukan 2026); untuk web awal gunakan Blade, lanjut Livewire bila sesuai kebutuhan.
  • Mobile: Dart dan Flutter; mulai setelah API matang supaya Anda memahami batas antara klien, layanan, dan penyimpanan data.
  • Tahap pilihan: React + TypeScript untuk aplikasi antarmuka kompleks, Redis untuk cache/antrian, Docker untuk lingkungan yang konsisten; tidak wajib untuk proyek pertama.

Catatan versi per 28 Oktober 2026: Laravel 13 stabil (membutuhkan PHP 8.3+; lihat matriks kompatibilitas resmi); PHP 8.5 didukung; Flutter 3.47 stabil (rilis Agustus 2026; 3.50 dijadwalkan November); Node.js 24 berstatus LTS, sedangkan Node 26 masih Current; PostgreSQL 18 stabil, PostgreSQL 19 masih RC dan GA direncanakan November; OWASP Top 10:2025 adalah rujukan keamanan web terkini. Jangan menyamakan versi terbaru dengan pilihan produksi terbaik; pilih rilis stabil didukung dan cocok dengan library serta lingkungan proyek.

Cara belajar: siklus 5 langkah

  1. Pahami: definisikan masalah, masukan, keluaran, batasan, dan contoh kasus.
  2. Prediksi: sebelum menjalankan contoh, tuliskan perkiraan hasilnya.
  3. Implementasikan: ketik, jalankan, dan amati hasil; jangan hanya salin-tempel.
  4. Uji dan perbaiki: coba input kosong, angka negatif, data besar, gagal jaringan, dan akses tanpa izin.
  5. Jelaskan dan simpan: tulis README singkat, commit di Git, dan terangkan keputusan desain dengan bahasa sendiri.

Ritme setiap minggu: 2 jam teori + 4–6 jam praktik + 1–2 jam debugging dan review + 1–2 jam proyek. Satu latihan tanpa bantuan AI pada setiap modul agar pemahaman tidak semu. Gunakan AI untuk penjelasan alternatif, review kode, dan merumuskan test case; jangan menyerahkan keputusan keamanan atau hasil pengujian pada AI tanpa verifikasi.

Struktur proyek akhir

Proyek Buku Kebutuhan Siaga: pengguna menentukan jumlah anggota keluarga; aplikasi menghitung kebutuhan default, pengguna menyesuaikan item; tersedia kategori dan subkategori, checklist, stok, tanggal kedaluwarsa, informasi kesiapsiagaan, dan mode offline mobile terbatas. Pelajari sebagai kasus rekayasa perangkat lunak, bukan sumber tunggal saran keselamatan. Kebutuhan bencana harus disesuaikan dengan panduan resmi dan kondisi wilayah.

Artefak: PRD singkat, ERD, API contract, repo backend, repo Flutter, migration, seed, test, keamanan dasar, README, hasil pengujian, backup, panduan deployment. Uraian lebih lengkap pada bab proyek.

Definisi selesai dan aturan kelulusan

Sebuah tugas belum selesai jika hanya tampil bagus. Definisi selesai: memenuhi kriteria penerimaan, tidak ada error kritis, validasi server bekerja, respons kesalahan ditangani, tes utama lulus, dokumentasi perintah instalasi tersedia, kode di-commit, dan bisa dijalankan ulang dari lingkungan bersih. Jangan lanjut ke fase berikut bila tidak bisa menjelaskan sendiri contoh yang ditulis.
