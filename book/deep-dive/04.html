Bagian III — Database, PHP, dan Laravel

16. Memodelkan data dengan ERD dan normalisasi

Relational database menyimpan data dalam tabel dengan relasi. Primary key (PK) mengidentifikasi baris secara unik; foreign key (FK) menjaga hubungan; unique membatasi duplikat; not null melarang kosong; check membatasi nilai. Model data mengikuti kebutuhan bisnis, bukan struktur halaman UI. Satu tabel raksasa dengan kolom kategori1, kategori2, item1, item2 adalah desain sulit berkembang.

Contoh model aplikasi checklist multi-pengguna:

  • users(id, name, email, password_hash, created_at); email unik, password hanya berupa hash kuat dari mekanisme bawaan framework.
  • categories(id, user_id, parent_id, name); parent_id nullable untuk mendukung subkategori dan FK ke categories sendiri.
  • items(id, user_id, category_id, name, unit, default_qty, current_qty, checked, expires_on).
  • checklist_events(id, item_id, actor_user_id, event_type, occurred_at) untuk audit perubahan relevan.

Relasi users 1:N items, categories 1:N items, categories 1:N categories. Jika template kebutuhan global digunakan bersama banyak pengguna, pisahkan template_items dari user_items sehingga perubahan default tidak menimpa kustomisasi pengguna. Normalisasi menghindari duplikasi dan update anomaly: simpan nama kategori di tabel kategori dan referensikan category_id, jangan salin teks kategori di seluruh item tanpa alasan. Denormalisasi boleh dilakukan bila ada kebutuhan performa terukur.

Praktik: gambar ERD dengan crow's foot untuk users, categories, items, item_logs; tentukan bagaimana sistem mencegah item milik user A menunjuk kategori milik user B. Tes keluar: dapat menjelaskan constraint mana yang dijamin database dan mana yang wajib divalidasi lapisan aplikasi.

17. SQL: membuat tabel dan mengambil data

DDL seperti CREATE TABLE, DML seperti INSERT/UPDATE/DELETE, query seperti SELECT. SQL memakai logika set; jangan selalu memikirkan pemrosesan baris demi baris. Gunakan WHERE sebelum UPDATE dan DELETE, serta transaction pada perubahan banyak tabel. Contoh berikut menggunakan PostgreSQL.

CREATE TABLE categories (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name VARCHAR(120) NOT NULL UNIQUE
);
CREATE TABLE items (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  category_id BIGINT NOT NULL REFERENCES categories(id),
  name VARCHAR(120) NOT NULL,
  quantity INTEGER NOT NULL DEFAULT 0 CHECK (quantity >= 0),
  checked BOOLEAN NOT NULL DEFAULT FALSE
);
INSERT INTO categories(name) VALUES ('P3K'), ('Air dan Pangan');
INSERT INTO items(category_id,name,quantity)
VALUES (1,'Perban',2), (2,'Air kemasan',6);
SELECT c.name AS category, i.name, i.quantity
FROM items i JOIN categories c ON c.id = i.category_id
WHERE i.quantity > 0 ORDER BY c.name, i.name;

Query lanjut: GROUP BY untuk agregasi; HAVING menyaring hasil grup; LEFT JOIN menampilkan kategori yang belum punya item; COALESCE menangani null dengan nilai pengganti; ORDER BY ... LIMIT ... OFFSET untuk halaman data sederhana (pada data besar pertimbangkan keyset pagination). Jangan membangun SQL dengan menggabungkan string input pengguna: gunakan parameter binding atau ORM.

SELECT c.name, COUNT(i.id) AS banyak_item,
       COALESCE(SUM(i.quantity), 0) AS total_unit
FROM categories c LEFT JOIN items i ON i.category_id = c.id
GROUP BY c.id, c.name
ORDER BY banyak_item DESC;

Praktik: tulis 25 query: 5 CRUD, 5 WHERE/ORDER, 5 JOIN, 5 agregasi, 5 kasus null/pagination. Buat juga query untuk mencari item kedaluwarsa dan kategori tanpa item. Tes keluar: tahu perbedaan filter WHERE sebelum agregasi dan HAVING setelah agregasi.

18. Transaksi, konkurensi, indeks, dan backup

Transaksi mengelompokkan perubahan atomik: semua berhasil atau semuanya dibatalkan. ACID: Atomicity, Consistency, Isolation, Durability. Contoh transfer stok dari gudang A ke B perlu mengurangi A dan menambah B dalam satu transaksi dengan pengecekan saldo. Perhatikan race condition: dua permintaan bersamaan dapat melewati pengecekan bila tanpa locking atau strategi atomik.

BEGIN;
UPDATE items SET quantity = quantity - 1
WHERE id = 1 AND quantity >= 1
RETURNING quantity;
-- Di aplikasi: jika tidak ada baris ter-update, ROLLBACK, jangan lanjut.
-- Operasi terkait lain dilakukan hanya bila pengurangan berhasil.
COMMIT;

Indeks mempercepat pola baca tertentu tetapi membutuhkan ruang dan memperlambat sebagian write. Buat berdasarkan query nyata: FK sering perlu indeks tersendiri, kolom filter/sort populer dapat diindeks, cek dengan EXPLAIN (ANALYZE, BUFFERS) pada lingkungan aman dan data representatif. Jangan mempublikasikan hasil EXPLAIN ANALYZE yang membocorkan data sensitif.

Backup bukan sekadar file dump: tetapkan RPO (berapa kehilangan data yang bisa ditoleransi) dan RTO (berapa lama layanan bisa dipulihkan), jadwalkan backup, enkripsi dan batasi akses, simpan salinan terpisah, serta uji restore. Untuk database besar pertimbangkan physical backup/WAL sesuai kebijakan; latihan awal cukup pg_dump dan pg_restore ke database uji, jangan melakukan restore langsung ke produksi.

Praktik: buat transaksi stok dan simulasikan error, pastikan seluruh perubahan batal. Buat indeks untuk query filter, bandingkan rencana eksekusi secara kritis. Dokumentasikan prosedur restore staging. Tes keluar: dapat menjelaskan mengapa dua request bersamaan memerlukan desain khusus.

19. PHP: dari skrip menjadi kode terstruktur

PHP berjalan di server, sedangkan JavaScript halaman berjalan di browser. PHP modern mendukung strict types, type declarations, enum, class, interface, exception, namespace, Composer dan autoloading. Pelajari ini sebelum bergantung pada Laravel. Gunakan declare(strict_types=1) pada contoh untuk membangun kebiasaan tipe yang eksplisit.

<?php
declare(strict_types=1);

function hitungTotal(int $harga, int $jumlah): int
{
    if ($harga < 0 || $jumlah < 1) {
        throw new InvalidArgumentException('Input tidak valid');
    }
    return $harga * $jumlah;
}

echo hitungTotal(25000, 3); // 75000

OOP: object menggabungkan data dan perilaku; class blueprint, constructor menginisialisasi, interface adalah kontrak, dependency injection memberikan dependensi dari luar agar testable. Jangan membuat inheritance dalam-dalam ketika composition lebih sederhana. Controller bukan tempat semua SQL dan aturan bisnis ditumpuk. Mulailah dari fungsi kecil dan class sewajarnya.

Praktik: buat Item, ItemRepositoryInterface, dan InMemoryItemRepository; uji tambah/hapus tanpa database. Tes keluar: jelaskan keuntungan interface terhadap penggantian implementasi repository.

20. Laravel request lifecycle, MVC, Blade

Laravel mengatur request melalui entry point, middleware, router, controller, service/model, kemudian response. Route memilih handler; controller mengatur alur request; request validation memeriksa data masuk; model/Eloquent merepresentasikan data; view Blade merender HTML. Pelajari php artisan route:list, php artisan migrate, php artisan test, composer install, dan file konfigurasi config/. Jangan memodifikasi kode di vendor/.

// routes/web.php (sebagai contoh setelah proyek Laravel dibuat)
use App\Http\Controllers\ItemController;
use Illuminate\Support\Facades\Route;

Route::middleware('auth')->group(function () {
    Route::get('/items', [ItemController::class, 'index'])->name('items.index');
});

Tata letak minimal: routes/web.php untuk web session, routes/api.php untuk API setelah scaffolding yang sesuai, app/Http/Controllers, app/Models, database/migrations, resources/views, tests/Feature. Perhatikan struktur starter kit bisa berbeda per versi; cek perintah resmi proyek terpasang.

Praktik: buat halaman daftar dan form item dengan Blade, gunakan layout konsisten, validasi feedback, serta token CSRF pada form browser. Tes keluar: dapat menjelaskan beda 302 redirect ke login, 401 response API, dan 403 akses terlarang.

21. Laravel migrations, Eloquent, validation, authorization

Migration mendefinisikan evolusi struktur database secara version-controlled, seeder memuat data contoh/default, factory membuat data pengujian. Eloquent memudahkan CRUD dan relasi, tetapi tetap perlu memahami SQL agar menghindari N+1 query. Gunakan eager loading (with) bila menampilkan banyak relasi. Model memiliki $fillable/atribut guarded; jangan menerima seluruh field dari request tanpa membatasi yang boleh diubah.

// Contoh logika controller setelah model + migration + policy tersedia
public function store(\Illuminate\Http\Request $request)
{
    $data = $request->validate([
        'name' => ['required', 'string', 'min:2', 'max:120'],
        'quantity' => ['required', 'integer', 'min:0', 'max:100000'],
    ]);

    $item = $request->user()->items()->create($data);
    return response()->json(['data' => $item], 201);
}

Kode contoh parsial, bukan controller lengkap: memerlukan relasi items() pada model User, migration, auth middleware dan konfigurasi API. user_id sengaja diambil dari sesi/token terautentikasi, bukan input client. Untuk membaca/mengubah item berdasarkan ID, gunakan query yang dibatasi pemilik atau Policy/Gate (authorize): mengetahui ID tidak berarti berhak mengakses. Jangan sekadar menyembunyikan tombol admin di UI karena pemeriksaan tetap wajib di server.

Praktik: buat policies untuk view/update/delete item; uji dua pengguna yang mencoba mengubah item satu sama lain. Tes keluar: 403/404 sesuai desain dan data tidak berubah saat akses ditolak.

22. Authentication, session, API token dan keamanan

Authentication menjawab siapa pengguna; authorization menjawab apa yang boleh dilakukan. Pada aplikasi web Laravel tradisional gunakan session/cookie + CSRF protection. Untuk mobile via API, Laravel Sanctum dapat menerbitkan token per perangkat melalui jalur resmi yang terdokumentasi; token dikirim via Authorization: Bearer ... melalui HTTPS. Simpan token mobile menggunakan penyimpanan aman platform, bukan hardcoded, log, URL query, atau repository. Desain logout/revoke token dan token expiry sesuai risiko.

Praktik keamanan dasar: validasi sisi server; output escaping; periksa ownership setiap resource; hash password melalui fasilitas framework; gunakan TLS; rate-limit login; jangan tampilkan stack trace produksi; simpan secrets di environment/secret manager; lakukan rotasi kredensial; update dependensi; audit semua upload file (jenis, ukuran, lokasi), aktifkan pembatasan CORS sesuai asal yang dipercaya.

OWASP Top 10:2025 mencakup broken access control, security misconfiguration, software supply chain failures, cryptographic failures, injection, insecure design, authentication failures, integrity failures, logging and alerting failures, serta mishandling of exceptional conditions. Ini adalah kerangka risiko; bukan daftar periksa yang otomatis membuktikan aman.

Praktik: uji IDOR: user B meminta /api/v1/items/{id-milik-A}. Harus ditolak. Periksa respons validasi HTML/JSON, escape output, rate limit, dan masa hidup token. Tes keluar: memahami perbedaan 401 vs 403, CSRF vs XSS, SQL injection vs IDOR.

23. Testing dan rekayasa kode Laravel

Testing pyramid: unit untuk fungsi murni, feature/integration untuk request+DB dan otorisasi, end-to-end untuk perjalanan pengguna. Test tidak hanya happy path: coba input invalid, race condition, user lain, item hilang, DB error, jaringan gagal. PHP ecosystem menyediakan PHPUnit/Pest; Laravel mendukung feature tests dengan request helpers dan refresh database.

// Contoh pola feature test (sesuaikan factory, auth, dan route proyek)
it('rejects negative quantity', function () {
    $user = \App\Models\User::factory()->create();
    $this->actingAs($user)
        ->postJson('/api/v1/items', ['name' => 'Perban', 'quantity' => -1])
        ->assertUnprocessable()
        ->assertJsonValidationErrors('quantity');
});

Lakukan formatting/linting (Laravel Pint, PHPStan/Larastan bila relevan), code review kecil, analisis static, pengujian sebelum merge. Hindari overengineering: service/repository layer hanya bila memecahkan kebutuhan nyata, bukan demi diagram kelas. Catat trade-off di ADR singkat (Architecture Decision Record): konteks, opsi, keputusan, konsekuensi.

Praktik: setidaknya 3 unit tests, 5 feature tests termasuk IDOR dan validasi, 1 test proses login. Tes keluar: tes tetap stabil ketika dijalankan ulang dan tidak bergantung pada urutan eksekusi.
