Bagian I — Fundamental Ilmu Pemrograman

1. Apa itu program dan apa itu algoritma?

Program ialah instruksi yang dieksekusi komputer; algoritma adalah urutan langkah logis berhingga yang memecahkan masalah. Algoritma berbeda dari bahasa: logika menghitung diskon sama walaupun diterapkan di JavaScript, PHP, atau Dart. Input adalah data masuk, proses transformasi, output hasil; ketiganya dapat dipetakan sebelum menulis kode.

Contoh: total belanja. Input: harga satuan (bilangan >=0), jumlah (>0), persentase diskon (0–100). Proses: subtotal = harga × jumlah; potongan = subtotal × diskon/100; total = subtotal − potongan. Output: jumlah yang dibayar. Kasus batas: diskon 0%, diskon 100%, harga nol, jumlah nol, data bukan angka, bilangan desimal. Pengecekan ini disebut validasi dan harus dilakukan sebelum proses.

Pseudocode:

BACA harga, jumlah, diskon
JIKA harga < 0 ATAU jumlah <= 0 ATAU diskon < 0 ATAU diskon > 100
    TAMPILKAN "Input tidak valid"
LAINNYA
    subtotal ← harga × jumlah
    total ← subtotal × (1 − diskon / 100)
    TAMPILKAN total
SELESAI

Latihan: (A) ubah logika di atas agar diskon berlaku hanya bila subtotal >= 100000; (B) buat algoritma menghitung rata-rata nilai 5 siswa; (C) tuliskan penanganan data kosong; (D) gambarkan flowchart sederhana; (E) jelaskan mengapa diskon 110% harus ditolak. Tuntas bila: Anda mampu menjelaskan tiap cabang tanpa menyebut sintaks bahasa tertentu.

2. Cara komputer, OS, jaringan, dan web bekerja

CPU mengeksekusi instruksi, RAM menyimpan data kerja sementara, penyimpanan menyimpan file persisten, sistem operasi mengelola proses dan akses file, jaringan mengantarkan paket antarmesin. Browser menjalankan HTML (struktur), CSS (tampilan), JavaScript (interaksi), lalu berbicara dengan server lewat HTTP(S). Server menerapkan aturan bisnis dan membaca database. Database bukan tempat menyimpan password mentah, file kode, atau seluruh gambar besar secara otomatis; tergantung desain, metadata ada di DB dan file bisa di object storage.

Alur saat membuka aplikasi: DNS menerjemahkan domain → browser membuat koneksi TLS untuk HTTPS → browser mengirim request HTTP → reverse proxy/server aplikasi memproses → aplikasi melakukan query terotorisasi → server mengirim status/body → browser merender. DNS, TLS, HTTP, session, SQL adalah konsep berbeda; menghafal istilah tanpa memahami alur sering menyebabkan salah diagnosis.

Istilah inti: IP = alamat jaringan; domain = nama yang dicari melalui DNS; port = tujuan layanan dalam host; URL = lokasi resource; HTTPS = HTTP dalam koneksi terenkripsi; cookie = data kecil pada browser sesuai aturan atributnya; session = keadaan autentikasi yang biasanya disimpan/dirujuk di server; API = kontrak untuk komunikasi antarkomponen.

Latihan: gambar alur login dari Flutter → HTTPS → Laravel → PostgreSQL → response. Bedakan apa yang berjalan di HP vs server. Jelaskan apa yang terjadi bila DNS salah, port tertutup, database mati, dan token tidak berlaku. Tuntas bila: Anda bisa membedakan error jaringan (misalnya timeout) dari error validasi (422) dan error autentikasi (401).

4. Variabel, tipe, operator, dan ekspresi

Variabel memberi nama sebuah nilai. Pada JavaScript, const default untuk nilai yang tidak akan di-reassign, let bila perlu berubah; hindari var untuk kode baru. Tipe umum: number, string, boolean, null, undefined, object. Nama variabel sebaiknya menjelaskan maksud (jumlahPeserta, bukan jp), satuan (durasiMenit), dan konteks (hargaRupiah). JavaScript memiliki representasi angka floating point; berhati-hatilah pada uang dan desimal.

const harga = 25000;
const jumlah = 3;
const diskon = 10; // persen
const subtotal = harga * jumlah;
const total = subtotal * (1 - diskon / 100);
console.log({ subtotal, total }); // 75000, 67500

Operator aritmetika: + - * / % **. Perbandingan: ===, !==, <, <=, >, >=. Logika: && (dan), || (atau), ! (tidak). Gunakan ===, bukan ==, sebagai pilihan awal agar perbandingan tidak melakukan konversi tipe implisit. Ekspresi 0.1 + 0.2 bukan selalu tepat 0.3; untuk rupiah bulat simpan unit terkecil sebagai integer, untuk mata uang pecahan gunakan strategi decimal/integer berdasarkan domain.

Latihan: implementasikan tarif parkir: 1 jam pertama Rp4.000; jam berikutnya Rp2.000 per jam yang dibulatkan ke atas; durasi <=0 ditolak. Buat 5 contoh: 30 menit, 60 menit, 61 menit, 180 menit, -1 menit. Tuntas bila: setiap hasil diuji secara manual dan dengan kode.

5. Percabangan, loop, dan pengendalian alur

if/else membuat keputusan, switch menangani pilihan diskrit, for untuk iterasi yang diketahui, while jika berhenti berdasarkan kondisi. Hindari loop tanpa perubahan kondisi karena bisa tak berakhir. Biasakan guard clause: tolak kondisi tidak valid di awal fungsi, baru proses logika utama.

function kategoriStok(jumlah) {
  if (!Number.isInteger(jumlah) || jumlah < 0) {
    throw new Error('Jumlah harus bilangan bulat tidak negatif');
  }
  if (jumlah === 0) return 'habis';
  if (jumlah < 5) return 'menipis';
  return 'cukup';
}
for (const n of [0, 2, 7]) console.log(n, kategoriStok(n));

Latihan: tulis fungsi FizzBuzz 1–30, tetapi mulai dari analisis kelipatan 3 dan 5; buat program menentukan apakah tahun kabisat; buat perulangan untuk menghitung total item valid dan abaikan jumlah negatif. Tuntas bila: tidak ada loop tak terbatas dan semua cabang diuji.

6. Function, parameter, return, scope

Fungsi mengemas pekerjaan kecil yang bisa diuji ulang. Input melalui parameter, hasil melalui return, tidak menyembunyikan perubahan global yang sulit dilacak. Bedakan fungsi murni (hasil bergantung pada input, tanpa efek samping) dari fungsi dengan side effect (menulis file, HTTP, UI). Fungsi murni lebih mudah diuji.

function hitungKebutuhan(jumlahOrang, literPerOrangPerHari, hari) {
  if (![jumlahOrang, literPerOrangPerHari, hari].every(Number.isFinite)) {
    throw new TypeError('Semua input harus angka');
  }
  if (jumlahOrang <= 0 || literPerOrangPerHari <= 0 || hari <= 0) {
    throw new RangeError('Input harus positif');
  }
  return jumlahOrang * literPerOrangPerHari * hari;
}
console.log(hitungKebutuhan(3, 3, 3)); // 27 liter (asumsi latihan)

Angka 3 liter/hari pada contoh hanyalah parameter latihan matematis, bukan rekomendasi medis/kebencanaan universal. Untuk sistem nyata, nilai default harus mengikuti pedoman yang divalidasi dan dapat disesuaikan pengguna.

Latihan: pecah program kasir menjadi validasiItem, hitungSubtotal, hitungDiskon, formatRupiah; jangan gabungkan logika dengan prompt atau DOM. Tuntas bila: fungsi bisa dipanggil dari Console/Node tanpa halaman web.

7. Array, object, Map, Set, dan struktur data

Array adalah daftar terurut, object memodelkan entitas dengan properti, Map untuk key-value yang dinamis, Set untuk nilai unik. Pilih berdasarkan operasi: daftar item → array; detail item → object; cek duplikasi ID → Set; indeks berdasarkan key → Map. filter, map, find, reduce, some, every adalah operasi array yang sering dipakai.

const items = [
  { id: 1, nama: 'Air', jumlah: 6, checked: true },
  { id: 2, nama: 'Senter', jumlah: 1, checked: false },
  { id: 3, nama: 'Baterai', jumlah: 4, checked: true },
];
const yangBelum = items.filter(item => !item.checked);
const jumlahSeluruh = items.reduce((sum, item) => sum + item.jumlah, 0);
console.log(yangBelum, jumlahSeluruh); // Senter, 11

Mutasi (push, mengubah properti) berbeda dari membuat array/object baru (map, spread). Di antarmuka reaktif, perubahan referensi immutable sering membuat pembaruan state lebih mudah diprediksi.

Latihan: buat daftar tugas dengan id unik, tambah, ubah status, hapus, cari item berdasarkan id, hitung persentase selesai. Test kasus daftar kosong dan ID tidak ditemukan. Tuntas bila: fungsi tidak bergantung pada urutan item saat mencari berdasarkan ID.

8. Problem solving, kompleksitas, dan debugging

Pisahkan symptom (halaman kosong) dari root cause (response API bukan JSON). Reproduksi, catat input, baca stack trace dari baris pertama yang relevan, perkecil kasus, buat hipotesis, uji satu perubahan pada satu waktu, dan tulis regression test. Kompleksitas O(n) berarti waktu bertambah sebanding jumlah data, O(n²) sering muncul pada nested loop, O(1) operasi tetap secara model, O(log n) pencarian pada struktur terurut tertentu. Tidak semua program butuh optimasi; ukur dulu.

Contoh test sederhana tanpa library:

function tambah(a, b) { return a + b; }
function assertEqual(actual, expected) {
  if (actual !== expected) throw new Error(`${actual} != ${expected}`);
}
assertEqual(tambah(2, 3), 5);
assertEqual(tambah(-1, 1), 0);
console.log('2 test lulus');

Latihan: sengaja buat bug i <= array.length, amati item undefined, kemudian perbaiki. Bandingkan mencari ID dalam array besar menggunakan find dan Map. Tuntas bila: laporan bug berisi langkah reproduksi, hasil yang diharapkan, hasil aktual, akar masalah, serta uji regresi.

9. Git: sejarah perubahan dan kerja profesional

Git melacak perubahan snapshot file. Commit kecil dan bermakna lebih baik daripada satu commit raksasa. Branch untuk fitur/eksperimen, pull request atau merge request untuk review. Git bukan pengganti backup database atau rahasia. Jangan commit .env, token, password, data warga, kunci privat, atau node_modules.

git init
git add README.md
git commit -m "docs: tulis petunjuk proyek"
git switch -c feat/checklist
# edit kode lalu:
git add .
git diff --cached
git commit -m "feat: tambah validasi jumlah item"

Konvensi sederhana: feat:, fix:, docs:, test:, refactor:. Periksa git diff sebelum commit; jangan menjalankan git reset --hard atau force push pada branch bersama tanpa memahami dampaknya.

Latihan: buat branch fitur dan bugfix, lakukan masing-masing commit, tampilkan git log --oneline, lakukan merge lokal, lalu tulis README cara menjalankan proyek. Tuntas bila: perubahan bisa dijelaskan dari log dan rollback dapat direncanakan tanpa menghapus pekerjaan tim.
