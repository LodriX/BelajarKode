Bagian II — Web Fundamental: HTML, CSS, JavaScript, TypeScript

10. HTML: struktur, semantik, form, aksesibilitas

HTML adalah struktur dokumen, bukan bahasa pemrograman. Mulai dengan <!doctype html>, html lang="id", meta charset, meta viewport, judul halaman bermakna, satu h1 yang menjelaskan konteks, serta heading berjenjang. Gunakan header, nav, main, section, article, footer sesuai makna; jangan menggunakan div untuk semua hal. button untuk aksi, a untuk navigasi, label terkait input, alt gambar deskriptif bila informatif. Navigasi dengan keyboard dan pembaca layar merupakan kebutuhan dasar, bukan fitur tambahan.

<!doctype html>
<html lang="id">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Daftar Kebutuhan</title>
</head>
<body>
  <main>
    <h1>Daftar Kebutuhan</h1>
    <form id="formItem">
      <label for="nama">Nama item</label>
      <input id="nama" name="nama" required maxlength="80">
      <button type="submit">Tambahkan</button>
    </form>
    <ul id="daftar" aria-live="polite"></ul>
  </main>
  <script src="app.js" defer></script>
</body>
</html>

Validasi HTML (required, min, max) membantu pengalaman pengguna tetapi tidak menggantikan validasi server. Gunakan pesan error yang jelas dekat input, jangan mengandalkan warna merah saja, pastikan fokus keyboard terlihat.

Praktik: buat halaman profil, halaman daftar item, dan formulir tambah item. Matikan CSS lalu periksa apakah konten masih terstruktur. Navigasikan dengan tombol Tab. Tes keluar: semua input memiliki label dan tombol bisa diaktifkan dengan keyboard.

11. CSS: box model, layout responsif, desain sistem

Box model terdiri dari content, padding, border, margin. Gunakan box-sizing: border-box agar ukuran mudah diprediksi. Flexbox cocok untuk alur satu dimensi, Grid untuk layout dua dimensi. Gunakan ukuran relatif (rem, %, minmax, clamp) dan mobile-first: mulai tampilan layar kecil kemudian tambah media query pada kebutuhan desain, bukan berdasarkan merek ponsel.

*, *::before, *::after { box-sizing: border-box; }
:root {
  --brand: #155e75;
  --text: #15232a;
  --gap: 1rem;
}
body { margin: 0; font: 1rem/1.6 system-ui, sans-serif; color: var(--text); }
main { width: min(100% - 2rem, 70rem); margin-inline: auto; }
.grid { display: grid; grid-template-columns: 1fr; gap: var(--gap); }
button:focus-visible, input:focus-visible { outline: 3px solid #0c7c95; outline-offset: 2px; }
@media (min-width: 48rem) {
  .grid { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}

Prinsip visual: konsistensi jarak, hierarki tipografi, kontras teks, area sentuh cukup besar, dan tidak mengandalkan hover untuk tugas penting. Hindari fixed height untuk konten teks yang dapat memanjang. Uji pada lebar 320, 375, 768, dan 1280 CSS px serta zoom 200%.

Praktik: desain 3 komponen: card, form-field, status-badge dengan CSS variables. Gunakan grid untuk kartu dan flex untuk tombol. Tes keluar: tidak ada horizontal scrolling tak diinginkan di layar 320px.

12. DOM dan event: membuat aplikasi interaktif

DOM adalah representasi elemen HTML sebagai object yang bisa diakses JS. Event click, submit, input adalah sinyal interaksi. Hindari menyisipkan data pengguna melalui innerHTML karena berisiko XSS; gunakan textContent atau buat node dan lampirkan secara eksplisit. State adalah sumber kebenaran data; tampilan hanya representasi dari state tersebut.

const form = document.querySelector('#formItem');
const daftar = document.querySelector('#daftar');
const items = [];

function render() {
  daftar.replaceChildren();
  for (const item of items) {
    const li = document.createElement('li');
    li.textContent = item.nama;
    daftar.append(li);
  }
}
form.addEventListener('submit', event => {
  event.preventDefault();
  const nama = form.elements.nama.value.trim();
  if (nama.length < 2) return;
  items.push({ id: crypto.randomUUID(), nama });
  form.reset();
  render();
});

Data dalam contoh hanya hidup selama halaman aktif. Untuk offline sederhana gunakan localStorage untuk data nonrahasia kecil; pahami ia sinkron, memiliki batas kapasitas, dan bukan penyimpanan tepercaya untuk token atau data sensitif. Untuk offline dengan query dan skala lebih besar, pelajari IndexedDB.

Praktik: tambah hapus, checkbox, filter belum selesai dan progress bar; simpan items sebagai JSON di localStorage; buat fungsi pemulihan yang menangani JSON rusak. Tes keluar: karakter <script> sebagai nama item harus terlihat sebagai teks, bukan dieksekusi.

13. HTTP, REST, JSON, dan asinkron

Browser mengirim request dengan method, URL, headers, dan body; server memberi status, headers, dan response. GET untuk membaca, POST membuat/aksi, PUT mengganti representasi, PATCH mengubah sebagian, DELETE menghapus. GET seharusnya aman dan tidak mengubah data. Status penting: 200 OK, 201 created, 204 no content, 400 bad request, 401 unauthenticated, 403 forbidden, 404 not found, 409 conflict, 422 validation, 429 rate limit, 500 kesalahan server.

JSON mendukung object, array, string, number, boolean, null; bukan undefined, komentar, atau tanggal sebagai tipe khusus. Field tanggal biasanya string ISO 8601 dan harus disepakati timezone-nya. Asinkron berarti program dapat melanjutkan pekerjaan sambil menunggu operasi seperti jaringan; Promise merepresentasikan hasil yang mungkin datang kemudian.

async function ambilItem() {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), 10000);
  try {
    const response = await fetch('/api/v1/items', {
      headers: { Accept: 'application/json' },
      signal: controller.signal,
    });
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } finally {
    clearTimeout(timeoutId);
  }
}

Penting: kode di atas membutuhkan server yang menyediakan /api/v1/items; belum dapat langsung dijalankan dalam file://. API publik bisa memiliki CORS, limit dan bentuk respons berbeda. Di UI selalu tampilkan state loading, empty, success, error, dan retry. Jangan membuat retry tanpa batas untuk request yang mengubah data karena berisiko duplikasi.

Praktik: buka DevTools Network dan analisis metode, status, header, durasi, request/response. Buat diagram apa yang terjadi jika server merespons 401 dan 500. Tes keluar: Anda bisa menjelaskan mengapa fetch tidak otomatis melempar exception hanya karena HTTP 404.

14. JavaScript modern, modules, dan TypeScript

Gunakan modul ES (export/import) agar fungsi terpisah dan dependensi eksplisit. npm mengelola paket dan lockfile (package-lock.json); gunakan LTS dan cek versi. Jangan menambahkan library untuk fungsi kecil yang bisa dibuat dengan API standar. TypeScript memperluas JavaScript dengan pemeriksaan tipe saat development; hasil akhirnya tetap JavaScript yang berjalan di browser. TypeScript bukan pengganti validasi input runtime karena JSON API dapat berisi data yang melanggar type yang Anda deklarasikan.

type Item = {
  id: string;
  nama: string;
  jumlah: number;
  checked: boolean;
};
function progres(items: Item[]): number {
  if (items.length === 0) return 0;
  const selesai = items.filter(item => item.checked).length;
  return Math.round((selesai / items.length) * 100);
}

Prinsip TS: aktifkan strict, berikan tipe pada kontrak publik, manfaatkan inferensi lokal, hindari any, gunakan unknown untuk data yang belum tervalidasi, cek null secara eksplisit, pisahkan API DTO dan domain model bila perlu. TS sesuai untuk frontend kompleks; proyek kecil Laravel Blade tidak wajib menambahkan TypeScript hanya demi tren.

Praktik: pindahkan fungsi progress dan item ke TypeScript; buat data sengaja salah (jumlah: '3') untuk melihat error kompilasi. Tambahkan pemeriksaan runtime ketika membaca localStorage. Tes keluar: pahami beda error kompilasi, error runtime, dan validasi di server.

15. UX, aksesibilitas, PWA, dan pemilihan frontend

Tampilan bukan hanya warna: pengguna membutuhkan status jelas, navigasi dapat diprediksi, pesan gagal yang bisa dipulihkan, konfirmasi untuk operasi destruktif, dan kontrol yang berfungsi pada ponsel. Gunakan WCAG 2.2 AA sebagai target aksesibilitas web: keyboard, teks alternatif, kontras, nama kontrol, target sentuh yang layak, serta status dinamis yang dibacakan dengan benar. Uji manual dengan keyboard dan pembaca layar; skor alat otomatis tidak menjamin aksesibilitas penuh.

PWA dapat menambahkan installability dan caching melalui web app manifest + service worker. Ia bukan sinonim aplikasi mobile native; kemampuan perangkat, penyimpanan, dan push notification bergantung platform. Untuk proyek offline-first, desain penyimpanan lokal, sinkronisasi, konflik, dan penghapusan data sejak awal. Cache asset tidak otomatis berarti data aman tersinkronisasi.

Kapan memilih: Blade/Livewire untuk dashboard form dan CRUD dominan di Laravel; Inertia + React/Vue saat pengalaman interaktif lebih kompleks; SPA terpisah saat frontend dan API memiliki siklus deployment independen; Flutter untuk aplikasi mobile lintas platform dengan pengalaman antarmuka mobile. Tidak perlu memaksakan microservices dan SPA untuk CRUD sederhana.

Proyek 1 — Web checklist offline

Spesifikasi: pengguna menambah/mengubah/menghapus item, memberi kategori, menentukan jumlah, menandai selesai, memfilter kategori, melihat persentase, dan mengekspor JSON. Responsif, tanpa login, penyimpanan lokal. Arsitektur awal: index.html, styles.css, app.js, core.js, README.md. core.js berisi fungsi data tanpa DOM; app.js menangani event/render.

Kriteria penerimaan: 1) tambah item valid, 2) item kosong/negatif ditolak, 3) edit berhasil, 4) hapus meminta konfirmasi, 5) persentase benar termasuk daftar kosong, 6) reload mempertahankan data, 7) JSON rusak ditangani, 8) keyboard berfungsi, 9) input HTML berbahaya aman, 10) semua perhitungan memiliki setidaknya 8 uji.

Refleksi wajib: jelaskan mengapa localStorage tidak cocok untuk login token, mengapa innerHTML tidak dipakai untuk data pengguna, dan bagaimana aplikasi berubah bila data harus digunakan bersama oleh 2 perangkat.
